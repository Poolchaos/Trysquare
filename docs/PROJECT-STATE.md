## Environment

- `TRYSQUARE_DATA` - the data root, default `~/.local/share/trysquare`. Holds
  `db.sqlite`, `projects/`, `runs/` and `exports/`.
- `TRYSQUARE_CLAUDE_PATH` - the binary reviews run through. Unset, it is the
  CLI path kept on Settings (the `claudePath` setting, read as each run
  starts and each check runs, D-152), then the
  Claude Code CLI installed as a dependency (`@anthropic-ai/claude-code`
  2.1.301, D-92), then `claude` on PATH. Every run records which one it used
  as a run note. Resolved by
  `src/server/engine/cli.ts`: a bare name is looked up on PATH (PATHEXT order
  on Windows), a `.js`/`.mjs` runs under Node, and on Windows an npm `.cmd`
  shim is read for the program it launches; anything else that cannot be
  started without a shell is refused by name.

## Settings

Stored in the `settings` table, edited on the settings screen. Only these keys
are accepted; anything else is refused by name.

- `maxConcurrentReviews` (default 1). Two reviews share one usage limit.
- `stageTimeoutMinutes` (default 20).
- `stageMaxBudgetUsd` (default 15). A ceiling on any single model call; zero
  removes the ceiling.
- `claudePath` (default empty). The CLI reviews run through, which
  `TRYSQUARE_CLAUDE_PATH` wins over (D-152).
- `defaultRulesetId` (default empty). The ruleset a new review starts on
  (D-225).
- `identities` (default empty). The git emails that count as the person's,
  for the Mine filter on a project's branches. Empty goes by `user.email`
  of their global git config, read each time and never stored (D-243).

## Structure

- `CLAUDE.md` - charter. `docs/` - specs, ledgers, plans.
- `src/lib/` - pure and I/O free, by folder: `domain` (enums, state
  machines, the shutdown order); `engine` (the CLI's arguments, its event
  stream, shell quoting, the sign-in command); `git` (diff and URL
  parsing, a branch pair kept apart, changed exported symbols, the changes
  read only as a pointer such as submodules and LFS files, a path inside
  a repository); `http` (the
  request guard); `models` (availability, effort support, full model ids,
  the second verifier's pairing); `projects` (a project's own checks and
  the environment their commands get); `review` (budget arithmetic,
  coverage, evidence, profiles, the quotation check, the report renderer,
  request planning, risk order, rule codes, the run summary, stage schemas,
  the five steps, mechanical sweeps, grading screens A to D, what a
  findings list says while it is empty, when a run's ending is said); `rulesets`
  (the ruleset's shape, import with a fidelity gate, prompt composition and
  batch planning, a directive section's name in words);
  `settings` (the CLI path, the emails that count as the person's); and
  paths, ids and matching an error by the
  name its class sets.
- `src/server/db/` - schema (16 tables), client, migrations 0000 to 0018, and
  repositories for projects, reviews, ledger, findings, models, rulesets,
  settings, stage executions, the scoreboard, a project's checks and what
  they found.
- `src/server/gitops/` - the only code under `src/` that spawns git (the
  setup and gate scripts under `scripts/` run it themselves), including the
  throwaway copy a project's own checks run in.
- `src/server/projectrun/` - the only code that spawns a project's own
  commands, in that copy (WP-I, D-196).
- `src/server/engine/` - the only code that spawns claude, plus the
  `ReviewEngine` seam and the interactive (Mode B) engine, which spawns
  nothing and exchanges prompt and answer files with a person's own session.
- `src/server/review/` - the pipeline, the verification stage's prompt and
  the checks on its verdicts, the engine runner, the checkpointing runner
  that makes a resumed stage free, the service that runs a review from a
  row, the project's checks within a review and the screenshots they
  saved, merged detection, and the report assembler.
- `src/server/jobs/` - the event bus, the job manager, and the SSE stream.
- `src/server/projects/` - cloning a project in the background.
- `src/server/runtime.ts` - the one door to the database and the job

## Known issues

- Not run, git-lfs not being on this machine: the throwaway copy a
  project's own checks run in is checked out with the person's git filters
  (`src/server/gitops/copy.ts`) after its remote is removed. With git-lfs
  configured, an LFS file there is either fetched from the host the
  repository's `.lfsconfig` names or fails the checkout (D-237).
- At 360px the top bar's navigation does not fit beside the "awaiting"
  badge: it scrolls sideways (`src/components/topbar.tsx`, `overflow-x-auto`
  on the nav), so its edge cuts the Rulesets label to "Ru" and Settings is
  reached only by scrolling it, with nothing to say so (seen 2026-11-17 in
  `review/2026-11-17-e2e/*-ruleset-image-as-words-phone.png`). The scroll
  is the design and stays (D-239): a phone is for watching a run and
  deciding findings, and the two cut off are setup screens.
- A ruleset's process directives show their markdown as written, where a
  rule's text is formatted (D-227; `plans/idea-inbox.md`). It is what the
  model is given, word for word.
- One Turbopack build warning remains, traced to the engine's per-review log
  paths, which cannot be static. It affects only the standalone output
  manifest, which this app does not use. Adopting `output: "standalone"`
  voids that acceptance; the re-check trigger is in `DECISIONS.md`.
- `npm audit --omit=dev` reports 0 vulnerabilities (2026-11-17, after next
  moved from 16.4.4 to 16.4.6, D-231; D-228 had moved it from 16.3.8 and zod
  from 4.4.3 to 4.6.7). The full audit reports 7 on 2026-11-19, all
  moderate and dev-only, one chain: through the typescript-eslint packages
  to `minimatch` below 11.0.1, accepted in D-228 (`npm audit` says a fix is
  available; `npm audit fix --dry-run` left that chain as it was on the
  morning of 2026-11-17). The 12 high to `picomatch` it reported on the
  evening of 2026-11-17, accepted in D-241, are no longer reported, nor is
  the `braces` chain D-89 accepted.
- An advisory against the installed next stops `next build` once, with exit
  1, when an AI session runs it, and prints text telling the agent what to
  do (D-231). The answer is the upgrade, by `npm install`.
- Next's build rewrites `tsconfig.json` (sets `jsx: react-jsx`, adds
  `.next/dev/types`). Run prettier on it after a build or the format gate
  fails on the next run.
- An interrupted Playwright run can leave its server holding port 3417, and
  the next `--e2e` then fails saying the port is in use. Reusing an existing
  server is deliberately not allowed, because it would run the journey
  against a server started without the fake engine.
- A ruleset's page at phone width keeps its controls at desk size: the
  on/off switch and the severity picker are smaller than a thumb. Its
  layout was put right on 2026-11-17 (each rule a stack, nothing past the
  card's edge); setup screens stay desktop-first (D-69).

## Not built

- More than one dependency per review: the model and the screens take a
  single linked project.
- More than one ruleset per review, so tiers compose: designed, not built.
- Emailing a report: in scope since D-251, not planned yet (what it means
  for the README's and SECURITY.md's lines: `plans/idea-inbox.md`,
  2026-07-30).
- Rules added, edited or removed in the app, and ruleset templates shipped
  with it: in scope since D-251, not planned yet. A rule can be switched
  off and its severity changed; its text comes only from an imported file.
- A viewer for a failed stage's transcript: the review page names the file
  and renders nothing of it (`01-ARCHITECTURE.md`, Not built yet).
- The live output of git while a project clones: a failure's stderr is
  shown, the running output is not (`04-UI-DESIGN.md`, Not built yet, which
  lists the screens' other unbuilt parts).
- Any authentication. This is a local, single-user tool by design.
